It failed before persisting the new partial ownership projection. The canonical bootstrap outcome remains `UNKNOWN_REQUIRES_RECONCILIATION`; the earlier successful private tests and offline CHANGE decision do not turn that failed startup into a success.

Source `887820300340dcc31a03f3dc46c31107e9aef9f3` initializes the dependency for the control-only branch. A regression exercises the actual cold `_start`, `_in_ns`, process creation, health probe, ownership capture and early projection. A separate external staged reproducer reaches the same public source boundary without importing candidate tests: the actual baseline fails and the corrected source passes under the normal isolated verifier. This evidence concerns deterministic engineering behavior, not local-model role competence.

A failed startup cannot silently restart. Independent OS-owner cleanup is a separate, narrowly reviewed, stop-only operation on the exact failed lifetimes. It must conserve native history, canonical ledger rows, the original mission, charged usage and the failed outcome. The source reconciliation API performs no signal, process cleanup, lease release, accounting reset or authority renewal.

An explicit complete set of four reconciliation flags lets the **same newly issued guardian** append a distinct reconciliation record. The original canonical issuer, intent, UNKNOWN result, source, control, profile, mission lineage and limits, store identity and Intent epoch must match. The independent cleanup evidence lives in the private owner directory outside the application volume. It binds the original processes, namespace and historical systemd invocation, full native and canonical-ledger fingerprints, unchanged stopped projection and OS-owner context.

Both append and consumption require current `D.current` authority, original B/C/D service scope, the canonical store and the normal Intent → GPU → stack → ACT fences. The receipt is consumed only by its exact returned identity and digest after fresh quiet-state checks. Evidence age is bounded by both MONOTONIC and BOOTTIME, including a final check after potentially blocking validation. Default behavior still refuses an unresolved UNKNOWN. An additional unresolved failure also refuses rather than broadening this one-pair continuation.

A systemd unit launched with `--collect` can disappear after its processes end. The evidence retains the historical invocation. A fresh observation may therefore show either the same loaded, nonactive invocation with PID zero, or the exact collected state: not found, inactive, PID zero and empty invocation. An active unit or a different nonempty invocation refuses.
