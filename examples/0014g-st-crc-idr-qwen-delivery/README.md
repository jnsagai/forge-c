# New Qwen-authored CRC IDR delivery experiment

Opt-in extension of qm-pipeline-demonstration-v1, named QM_DELIVERY_FIRST_DEMO
in its package report. It prepends native SWE.3 authorship and real compiler/
independent host checks to the existing six-phase graph. At most two correction
visits; no implementation code is seeded. The host/device fixture is test input,
not a driver. The reviewed reference retains its original identity and is not
silently imported as a newly approved requirements baseline.

Functional scope, process findings, authorship and release status are separate.
Target simulation/performance remains unproven until actually executed and
verified; host oracle/target compilation does not close the nine requirements.
Strict profiles and historical RCC/CRC work orders are unchanged.

See specs/014-durable-local-autonomy/DELIVERY-FIRST-E2E.md.

The explicitly selected `delivery_first.register_interface` binds a typed C
device interface to the frozen primary manual, device header and `IDR-API.h`.
The existing SWE.3 verifier compiles offset, width, volatility and signature
assertions with the selected target profile. This replaces this example's
incompatible legacy singleton-array expectation; unselected work orders retain
the legacy checks. Layout success establishes no functional or release result.
The API header supplies declarations only, expressing the existing contract.

Adding this input changes future prepared orders from 14 to 15 frozen inputs.
Prepare a new baseline/cohort before live evaluation; do not modify an existing
order, reuse an old authorization binding, or relabel the earlier three trials.
The adapter has local synthetic-fixture tests; native Qwen qualification is
NOT_RUN at introduction.
