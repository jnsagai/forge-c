# Generic embedded C boundary

Owner clarification, 30 October 2026: Forge-C must be a reusable factory for embedded C development, not an RCC implementation service. Passing these examples does not satisfy that requirement by itself.

Scheduling, admission, cumulative accounting, execution reconciliation, evidence binding, checkpoint reuse, learning disposition and quality routing belong to the shared engine. Device facts, requirement allocations, compiler/linker settings, memory layout, simulator/HIL models and project-specific acceptance criteria belong to declared inputs and target/project adapters. A model adapter must not silently change product scope or waive a criterion.

The latest changes fix shared mechanisms: author capacity, native visit accounting, complete literal scope reconstruction, current-validator checkpoint reuse, unit ordinals, current-header compilation, native reply contracts and selection of the declared hardware manual. Regression evidence includes RCC, IWDG and CRC paths. The differently named MANUAL42 test is a synthetic source-selection/negative-control test, not qualification of another physical device.

There are material remaining boundaries. The existing workflow templates and structured authoring paths still contain LL/HAL, register-oriented and Arm Cortex-M55 assumptions. Historical work orders also retain their RCC default when no peripheral is specified. Neither that default nor a successful RCC pipeline establishes support for an arbitrary application, RTOS component, bootloader, C API shape, compiler, core or MCU.

A future project must declare an appropriate engineering/target contract and independently verified tool path. Unsupported project obligations must produce an explicit scoped capability/input block while model-free supervision and unrelated eligible work continue. They must not be translated into RCC obligations merely to obtain a passing package.

Their results diagnose shared factory defects; they are not an apples-to-apples model benchmark. A controlled comparison must additionally match the engineering obligations, tool surface, role prompts and allowances and include all learning/adapter overhead.
