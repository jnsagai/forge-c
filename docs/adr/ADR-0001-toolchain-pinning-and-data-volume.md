# ADR-0001 — Toolchain pinning and data-volume layout

- **Status:** Accepted (implementation baseline, 2026-10-14)
- **Tasks:** T001, T002, T003 · **FR:** FR-039

## Context
The host root disk is ~91 % full and has no sudo. The bundled v0.1 demo needs Clang MC/DC
(`-fcoverage-mcdc`, Clang ≥ 18); only Clang 12/14 were installed. Fabro is shared with other live
projects on this workstation.

## Decision
1. All large/mutable factory data lives under `FORGE_DATA_ROOT` (default: the loop10 ext4 volume),
   configured by `scripts/forge-env.sh`: Python venv, uv/pip caches, Ollama models, Fabro storage,
   control-plane state and archives. The repository stays source-only.
2. Pinned, verified OSS toolchain:
   - LLVM **19.1.7** official release, digest verified against the GitHub build-provenance attestation
     (`toolchains/llvm-19.1.7.sha256`), prepended to `PATH` by `forge-env.sh`.
   - Ollama **0.34.0** standalone release (sha256 `cf958867…c0804`) on `127.0.0.1:11435`, models on the
     data volume. The root snap Ollama (:11434) is not used by Forge-C.
   - Model **qwen3:8b** (Apache-2.0, digest `500a1f067a9f`), 32k context, fully GPU-resident on the
     RTX 4070 8 GB (~41 tok/s measured). `max_concurrent_model_agents=1`.
   - Fabro **0.362.0-nightly.0** (`a192bce`, already installed at `~/.fabro/bin/fabro`). Not upgraded,
     because other projects depend on that binary (newer nightlies exist; upgrading is an explicit
     operator decision).
   - Python deps: `requirements/forge-factory.lock`, hash-pinned (`uv pip compile --generate-hashes`).
3. `tests/spec/validate_design.py` stays the design baseline; implementation progress is recorded in
   evidence, never by editing the authored registries' lifecycle fields.

## Consequences
- `evidence/v0.4/inventory/{tool-inventory.json,sbom.cdx.json,TOOL_MATRIX.md}` is regenerated by
  `python -m forge_factory.inventory`; missing optional tools (CBMC, Frama-C, Renode) are recorded as
  `MISSING` and their MCP operations are DISABLED, never emulated.
- The v0.1 demo evidence originally shipped is preserved verbatim in
  `evidence/v0.4/baseline/oss-demo-original/` (verified against the bundle `SHA256SUMS.txt`); reruns
  are stored separately.
