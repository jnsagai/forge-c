# ADR-0005 — Local-model runtime findings and compensations (night run 2026-10-14)

- **Status:** Accepted · **Tasks:** T007, T009, T018, T042, T046, T048 · **Evidence:** `evidence/v0.4/live/`,
  run archives `WO-0002-STM32N6-RCC-r1..r6`

| # | Observation (verified on Fabro 0.362 + Ollama 0.34 + qwen3:8b) | Decision |
|---|---|---|
| 1 | Ollama's VRAM-based default context is **4096**; Fabro's prompt with ~50 tool schemas was truncated, the model never saw tools and emitted tool calls as plain text. | `OLLAMA_CONTEXT_LENGTH=16384`, flash attention, q8_0 KV cache (`scripts/forge_services.sh`); verified 9 k-token prompt fully processed, model fully GPU-resident (6.2/8 GB). |
| 2 | 50 tool schemas per request waste tokens and invite denied calls. | Gateway offers only the role's permitted tools, detecting the role deterministically from the node's `use_skill` instruction; the policy hook remains the enforcement point. |
| 3 | "Follow the skill" was insufficient: the 8B model froze baselines before writing workproducts. | Node prompts are explicit numbered procedures (`workflow/prompts.py`): read → write (exact formats) → validate → freeze → reply. |
| 4 | Large tool outputs (a 300-line section index, multi-MB manuals) derail the model into summarising tool output. | Reference manual is deterministically split into ≤38 kB per-section files; prompts name the exact files; "continue with the next step, never summarise" rule. |
| 5 | Fabro's deterministic **failure-cycle breaker** (3 identical signatures) terminates the run before our bounded rework loop decides, and the in-graph `finalize` node never runs. `loop_restart_signature_limit` as graph attribute validates but is not honoured. | Exit-code variation proved insufficient (Fabro normalises numbers in signatures, run r9). The route gate blocks after **2** failed cycles (author rejections + failed inspections; within the authored maximum of 3) so the in-graph finalizer runs before the breaker; the supervisor's **external finalizer** packages every terminal run without a package (live-verified). |
| 6 | Small models send `"PASS"` strings where an object is expected. | `check_inspection` accepts bare verdicts; evidence ref defaults to the frozen baseline record; deterministic items are recomputed regardless. |
| 7 | A tool-error loop can run indefinitely inside one agent node. | T042 governor: per-visit turn cap in the policy hook (reset by a `stage_start` hook), node `timeout`, and token governor in the supervisor poll that cancels on reported-usage excess (live-verified on run `…5A4`). |
| 8 | Agent self-reported status is unreliable (`AGENT_OUTPUT_SCHEMA` on a correct repair). | Promotion, gates and packaging never rely on agent claims; only deterministic checks decide. |
| 9 | r10: in one SWE.3 context the HAL called LL functions never declared in the model's own LL header. `edit_file` with escaped `old_string` then looped until the 24k context was exhausted. | A separate `swe3_ll_author` node (fresh context) writes the LL header first. The HAL author may use only LL symbols declared there and must rewrite whole files on compile errors. The policy hook denies `edit_file` with an escaped `old_string` and gives an actionable reason. |
| 10 | r11: the SWE.2 author overwrote its architecture with its JSON status reply and froze it. The 8B inspector then **passed every checklist item** on a 127-byte JSON file. | No freeze of any workproduct that is an agent status reply. New deterministic checklist item **SWE2-07** (v0.4 overlay, additive) checks required sections, SWR allocation against SWE.1, unknown SWR references, and register offsets against the RM0486 section inputs. An 8B inspector's PASS is never treated as sufficient evidence on its own. |
| 11 | r12: target compile and clang analyzer PASS. However, the register-access macro that the prompt itself prescribed (an integer→pointer cast) raised MISRA 11.4, and the model used up its turn budget on it. Inline `cppcheck-suppress` comments would have hidden it. | MMIO uses an `extern volatile uint32_t ll_rcc_regs[N]` block placed by the linker, with no casts. Host tests define the array. The factory cppcheck op no longer honours `--inline-suppr`: an AI-written suppression is a self-granted deviation and is ignored. (The v0.1 static script is unchanged.) |
| 12 | r13: the model invented register offsets and masks (per-bit "offsets", `LSEON` at `0x1`). It rewrote the header 8× and exceeded its 128k token budget. The governor cancelled the run and the external finalizer sealed BLOCKED (fault path verified live). | Register definitions are data. A deterministic `swe3_regmap` node generates `LL_RCC_<REG>_OFFSET/_<FIELD>_POS/_MSK` from the RM0486 section inputs, for the registers in the inspected SWE.2 table. The LL author only adds inline functions. **SWE3-08** (verify node + inspection) re-checks every define against the RM. |
| 13 | r14 (reproduced in isolation against Ollama): in no-think mode qwen3:8b stops in the middle of long tool-call JSON, for example a whole C file in one `write_file`. Ollama 0.34 cannot parse it and returns **neither content nor a tool call**, so the node ends silently (outputs of 1.9k–4k tokens were lost). | Code is written as small skeletons with `//` marker lines, then one function group per `edit_file` (≤40 lines). SWE.3 runs as LL author, HAL author, then verify/fix/freeze. SWE.4 gains a unit-test author. Each node stays within the **authored** 20-call visit budget, which was not raised. The gateway now meters response shape (`content_chars`, `tool_calls`, `dropped_output`) without logging content. |
| 14 | r15: **false PASS** found on manual review. The model dropped the `*/` of a block-comment marker, so every HAL prototype and definition was commented out. Compile, guideline, register-map checks and the 8B inspector all passed an empty driver. The run then blocked in SWE.4, so no READY package resulted. | New deterministic **SWE3-09** (verify node, inspection, `validate_artifact implementation`). Every allocated `HAL_RCC_` function must be declared and defined non-static, every LL call must be defined, and there must be no commented-out code (MISRA Dir 4.4). Markers are now line comments. Lesson: every agent-produced artefact needs a deterministic *presence and completeness* check, not only a *conformance* check. |
| 15 | Model trial (user-approved): `qwen3-coder:30b` (30B MoE with ~3.3B active parameters, Q4 18.6 GB) runs on the SWE.3/SWE.4 code nodes only, via the Fabro per-node `model` attribute (live-verified in `stage.prompt` and the gateway meter). Isolated test: 3/3 large `write_file` calls parsed, against 0/2 for qwen3:8b. Throughput is about 29 tokens/s with 66% of the work on CPU and 34% on GPU (6.7 GB VRAM). In r19 the GPU averaged 47 W (max 79 W), swap stayed stable at 11–12 GB, and the run took about 22 minutes. r19's SWE.3 passed both compiles, the guideline, register map, completeness, clang analyzer and cppcheck checks, but ran out of the authored 20-call budget one call before freezing. | Opt-in `--code-model` profile; qwen3:8b stays the pinned default. The SWE.3/SWE.4 prompts were trimmed: no explicit freeze call (the deterministic gate freezes on PASS), no manifest read, and only the HAL files are read. The turn budget was not raised. Qwen3.6-35B-A3B was ruled out because the hardware can't run it (user). AirLLM-style layer paging was rejected because decoding is too slow for agent loops. |
| 16 | Cloud benchmark (user-authorized): DeepSeek Flash on an isolated Fabro :32291 behind a cost-capped gateway (key in the server vault only). Runs r21–r40 cost about US$0.01–0.03 each. A stronger model exposed **factory defects that qwen3:8b's leniency had hidden**: SWE.1 trace links failed because test files were planned but not yet written; inspectors had no checklist; the HAL prompt forced `(void)` signatures; SWR range IDs; `return f(x);` parsed as a declaration (86 false guideline violations); macros treated as API functions; `.`-separated verdict strings; prose before the contract JSON; authors exhausting the 20-call budget; inspectors re-running analyzers; a driver defining the register block; missing MISRA and resource records. With the scope set by the owner (RM0486 as hardware interface, safety out of scope), **r37 and r39 passed SWE.1–SWE.6**. An independent host re-run of r37 gave 23/23 unit and 28/28 integration checks passing; the HAL object is 640 B of code. | Each defect fixed generically with a regression test. The checklists and the 20-call budget are unchanged. SWE.3 is split into fix and evidence/design nodes, plus a `swe3_all` check. Edit chunk size is set per run (40 lines local, 150 cloud). A deterministic MISRA coverage matrix is generated (coverage, not compliance). Packages stay BLOCKED on genuine gaps: no target/simulator run (`target_verification`) and the safety documents deferred by the owner. qwen3:8b plus qwen3-coder:30b reached SWE.4 at best (token budget). |
| 17 | Revisiting #5 at the owner's request ("why BLOCKED instead of looping back?"). A model-free probe on Fabro 0.362 shows the breaker's signature is `node|category|failure message *including the command output*`, with digits normalised; it kills the run at the 3rd identical signature. The graph attribute `loop_restart_signature_limit` has no effect on it. When the failing script's output differs per cycle, the same graph loops six times and reaches the finalizer. | Every failed gate execution prints a distinct, digit-free marker (`gate execution <letters>` from the gate-log length). The route gate now applies the **authored** `maximum_rework_cycles` (3 in every SWE.1–SWE.6 checklist) instead of the earlier safety margin of 2, for all phases. The loop stays bounded by the route gate; the finalizer still packages BLOCKED after the authored budget is spent. |

| 18 | r56 (DeepSeek): the SWE.5 inspector wrote `SWE5-05=Rework finding: SWR-012/SWR-014 have no SWE.5 measure`. The verdict parser only knew PASS/FAIL/NOT_APPLICABLE, so the item became `FAIL:MISSING_VERDICT`: the finding was lost and the author was sent into rework without knowing what to fix, then exhausted its turn budget. | Fail synonyms (REWORK, REJECTED, FAILED, NOK) map to FAIL with the finding kept, because that is the conservative direction. PASS is accepted only as the literal word. `check_inspection` refuses an inspection that lacks a verdict for any required non-deterministic item (`INCOMPLETE_VERDICTS:<id>`, nothing recorded), so the inspector resubmits within its bounded visits. Regression tests are in `test_m2_mcp.py`. |
| 19 | r56 (DeepSeek): the SWE.6 author used all 20 tool calls reading and searching (for `forge_target_test.h` and `ForgeTarget`, which are factory-provided and live outside the workspace). Its first write hit the turn budget, so SWE.6 was REJECTED on every visit with no Robot suite and no report. | Same split as SWE.5: a `swe6_test_author` node (fresh context and its own budget) writes the scenarios and the Robot suite and runs `run_robot` until it PASSes. The SWE.6 author then gets the results, validates the trace and writes the report. Rework re-enters at the SWE.6 author. Test-author prompts state that the harness header and Robot library are provided, so the model does not search for them. The authored `max_turns` is unchanged. |
| 20 | r56: Fabro still killed the run with "deterministic failure cycle detected" on the 3rd identical SWE.6 author-gate rejection. The signature keeps only the first ~200 characters of the command output, and the #17 marker was printed last, so it was cut off on long outputs (the #17 probe used short ones). Separately, the supervisor's external finalizer asked only the local Fabro for run status: cloud runs got a 404 and were never packaged (r27, r49, r56). | The gate buffers its output and prints the per-execution marker as the first line. The test asserts it leads and is distinct within the first 40 characters. Launch writes `.forge-run/fabro_server.json` (URL and storage, no secret). `client_for_workspace()` is used by the finalizer's status probe and by token-usage collection. A test asserts the probe uses the recorded server and its token. Existing cloud work orders were backfilled and their missing packages were sealed BLOCKED by the supervisor. |
| 21 | r57 (DeepSeek, resumed at SWE.6): the Robot test author ignored `ForgeTarget`. It wrote a suite that imports `Process` and runs an invented `run_scenario.sh` with `shell=True`, and every test failed with exit 127. A Robot suite is code, so `run_robot` gave any SWE.6 author arbitrary command execution outside its MCP grant. Resume also left out the target ELF/map, so the package lacked `software/build/*.elf`/`*.map`. | `run_robot` now checks every suite statically before executing (`mcp/servers/robot_policy.py`). Only `Library ForgeTarget` is allowed: no Resource/Variables imports, no `${{…}}`, and no keyword names built from variables. Every keyword call, including setups, teardowns and templates, must be a ForgeTarget keyword, a keyword defined in the same file, or a BuiltIn subset with no evaluation or dynamic dispatch (Evaluate, Should Be True, Import Library and Run Keyword are excluded). Robot runs under `python -I`, so workspace modules cannot shadow imports. Tests prove a violating suite is refused before anything runs. The test-author prompt states the allowlist. Resume carries `build/target-cm55-gcc` only when SWE.3 is stable. |
| 22 | r59 (DeepSeek): the suite policy (#21) correctly refused a suite importing `OperatingSystem`/`Process`, but SWE.6 still failed. The test author spent its 20 calls exploring HAL sources, unit tests and the target tests, globbed for the suite, and even ran cppcheck, measure_elf and stack_usage, so it never wrote the suite. The report author then found no suite and also ran out of budget. | Same remedy as the SWE.4 harness (r16): a deterministic `swe6_scaffold` command node generates `test_rcc_requirements.robot` from the inspected SWE.1 baseline. It contains one test case per SWR with its tag and Robot-safe documentation, the allowed library, and the keyword reference in the header. Every body is `Fail    NOT IMPLEMENTED`, so the suite cannot pass until real target checks are written; a test proves 0/N pass. It never overwrites an authored suite. The test-author prompt reads exactly three files and rewrites the suite in one call. The generated workflow is now also validated with `fabro validate` before launch. |
