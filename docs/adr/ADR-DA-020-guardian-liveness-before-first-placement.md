# Guardian liveness before the first placement

The corrected owner host guard requires the exact current guardian's private heartbeat. The prior controller only wrote that heartbeat after `Placer.cycle()`, although a first placement invokes the guard inside that cycle. A fresh guardian would therefore spend a finite attempt before its own missing heartbeat refused launch. Publishing only once before the cycle also leaves a legitimate long synchronous stack/model startup vulnerable to the guard's existing 180-second freshness check.

The existing nonce-response guardian thread now atomically publishes private liveness before acknowledging its first valid challenge, and refreshes it on subsequent valid challenges at most every 15 seconds. No new thread, model call, scheduler, authority or role operation is introduced. The host guard already validates ordinary `current()` before reading the heartbeat, so its first and later checks observe responsive guardian liveness. Current authority, source, policies, Intent, kernel identity, fixed expiry and ownership checks remain unconditional.

Main publishes an in-progress cycle before placement and a completed-cycle observation only after the cycle returns and its audit row is written. An attestation refresh preserves the last completed cycle and completion timestamp; liveness never implies bootstrap readiness, engineering progress or a product PASS. Heartbeat writes use private temporary files, atomic replacement and fsync. Changed identity, damaged private metadata or storage failure refuses instead of fabricating an observation or falling back to another root.

Tests must exercise real nonce/socket responses, the heartbeat visible inside the first main cycle, later attestation refresh without advancing cycle completion, atomic publication and refusal of changed private identity. These controls establish no live role competence, driver completion or endurance. Deployment requires a newly qualified exact source and corresponding native/control/trial bindings; the currently running F0 guardian and failed B history remain unchanged.

The publisher also validates bounded prior metadata, rejects reopening an already completed cycle, and preserves its completion timestamp on duplicate completion. Non-object nonce requests are rejected before field access so malformed private clients cannot kill the existing nonce thread. That availability issue predates this heartbeat change and is not represented as a failed driver run or as the first-heartbeat causal symptom. No wall-clock ordering is imposed on completion observations; fixed MONOTONIC/BOOTTIME authority remains separate.
